# shadcn/ui

Component library — installation with `--all`, `components.json` config, RTL support, DirectionProvider, and usage patterns.

## Installation

```bash
pnpm dlx shadcn@latest init
pnpm dlx shadcn@latest add --all
```

> **Always use `--all`** when adding components. Never cherry-pick individual components.

`init` generates:
- `components.json` — project config
- `lib/utils.ts` — `cn()` helper (clsx + tailwind-merge)
- Updates `tailwind.config.ts` with shadcn paths and theme tokens

After init, `add --all` installs every available component into `components/ui/`.

## `components.json` Configuration

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": true,
  "tsx": true,
  "rtl": true,
  "tailwind": {
    "config": "tailwind.config.ts",
    "css": "app/globals.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/core/hooks"
  }
}
```

| Field | Purpose |
|-------|---------|
| `style` | Component style variant (e.g. `"new-york"`) |
| `rsc` | React Server Components support (`true`) |
| `tsx` | Use TypeScript (`true`) |
| `rtl` | Enable RTL logical properties (`true`) |
| `aliases.components` | Import alias — `@/components` |
| `aliases.utils` | Utils alias — `@/lib/utils` |
| `aliases.ui` | UI components alias — `@/components/ui` |

## Component File Structure

```
components/
├── ui/              # Generated by shadcn CLI — rarely hand-edited
│   ├── button.tsx
│   ├── dialog.tsx
│   ├── input.tsx
│   ├── popover.tsx
│   ├── select.tsx
│   ├── sidebar.tsx
│   └── ...
└── custom/          # Feature composites wrapping ui/ components
    ├── confirm-dialog.tsx
    └── data-table.tsx
```

> Generated `ui/` files are managed by the CLI. Never modify them for feature logic — wrap in `components/custom/` instead. See [Components & State](components-and-state.md) for the composites pattern.

## RTL Support

### Enable RTL

Set `"rtl": true` in `components.json`. This must be done **before** running the migration.

### Run Migration

```bash
pnpm dlx shadcn@latest migrate rtl
```

The migration converts physical CSS properties to logical equivalents:

| Before | After |
|--------|-------|
| `ml-4` | `ms-4` |
| `mr-4` | `me-4` |
| `left-*` | `start-*` |
| `right-*` | `end-*` |
| `text-left` | `text-start` |
| `text-right` | `text-end` |
| `slide-in-from-right` | `slide-in-from-end` |
| `slide-in-from-left` | `slide-in-from-start` |

To migrate specific files only:
```bash
pnpm dlx shadcn@latest migrate rtl src/components/ui/sidebar.tsx
```

### DirectionProvider

Install the direction component:
```bash
pnpm dlx shadcn@latest add direction
```

Integrate `DirectionProvider` in `app/layout.tsx`, wrapping the provider tree with the server-resolved direction:

```tsx
import { DirectionProvider } from "@/components/ui/direction";
import { getLanguage, getDirection } from "@/lib/tolgee/language";
import { getStaticData } from "@/lib/tolgee/server";
import { TolgeeNextProvider } from "@/lib/tolgee/client";

export default async function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  const language = await getLanguage();
  const direction = await getDirection();
  const staticData = await getStaticData();
  return (
    <html lang={language} dir={direction}>
      <body>
        <DirectionProvider direction={direction}>
          <RootProvider>
            <TolgeeNextProvider language={language} staticData={staticData}>
              {children}
            </TolgeeNextProvider>
          </RootProvider>
        </DirectionProvider>
      </body>
    </html>
  );
}
```

`DirectionProvider` wraps **outside** `RootProvider` because it needs the server-resolved `direction` prop. It feeds the direction value to all Radix primitives (popovers, dialogs, tooltips, etc.) so animations and positioning respect the current text direction.

See [Translations](translations.md) for `getDirection()` and `useDirection()` implementation.

### Icon Flipping

Add `rtl:rotate-180` to directional icons (arrows, chevrons):
```tsx
<ChevronRight className="h-4 w-4 rtl:rotate-180" />
```

### Portal Elements

Pass the `dir` prop to portal-based content components for correct animation direction:
```tsx
<PopoverContent dir={direction}>...</PopoverContent>
<DialogContent dir={direction}>...</DialogContent>
<TooltipContent dir={direction}>...</TooltipContent>
```

Without `dir`, portal elements render outside the `DirectionProvider` tree and may animate incorrectly.

### Manual RTL Components

After running `migrate rtl`, these components need manual RTL fixes:
- **Calendar** — day grid layout and navigation arrows
- **Pagination** — previous/next button order
- **Sidebar** — collapse direction and icon placement

## Usage Patterns

Import from `@/components/ui/`:
```tsx
import { Button } from "@/components/ui/button";
import { Dialog, DialogContent, DialogTrigger } from "@/components/ui/dialog";
import { Input } from "@/components/ui/input";
```

Composition example:
```tsx
import { Button } from "@/components/ui/button";
import { Dialog, DialogContent, DialogHeader, DialogTitle, DialogTrigger } from "@/components/ui/dialog";
import { Input } from "@/components/ui/input";

export function CreateProjectDialog() {
  return (
    <Dialog>
      <DialogTrigger asChild>
        <Button>New Project</Button>
      </DialogTrigger>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>Create Project</DialogTitle>
        </DialogHeader>
        <Input placeholder="Project name" />
        <Button type="submit">Create</Button>
      </DialogContent>
    </Dialog>
  );
}
```

> Never modify `components/ui/` for feature logic — wrap in `components/custom/`.

## CLI Quick Reference

| Command | Purpose |
|---------|---------|
| `pnpm dlx shadcn@latest init` | Initialize config + dependencies |
| `pnpm dlx shadcn@latest add --all` | Install all components |
| `pnpm dlx shadcn@latest add [name]` | Install single component |
| `pnpm dlx shadcn@latest add direction` | Install DirectionProvider for RTL |
| `pnpm dlx shadcn@latest migrate rtl` | Convert physical → logical CSS |
| `pnpm dlx shadcn@latest migrate rtl [path]` | Migrate specific files |
| `pnpm dlx shadcn@latest migrate radix` | Migrate to unified radix-ui package |
| `pnpm dlx shadcn@latest diff` | Check for upstream component updates |

## Key Rules

- Always use `--all` flag when adding components
- Never hand-edit `components/ui/` for feature logic — wrap in `components/custom/`
- Set `"rtl": true` in `components.json` before running `migrate rtl`
- Feed `DirectionProvider` the same direction value used for `<html dir>`
- Add `rtl:rotate-180` to all directional icons
- Pass `dir` prop to portal content components for correct animations
